# 要件定義（ドラフト）— 動画編集の定常作業をなくす

根拠：`現状分析.md`（月4本 / Before 40分/本 / 動画チーム4人 / YouTube一般公開 / 滞留なし）

## 目的

月4回の定常作業としての動画編集を、人の仕事として消す。

**設計原則（2026-11-21 本人）：人間の関与は入口と出口だけ。** 入口＝対象にするかの判断（基本設計では、録画取り込み後の確認依頼で吸収する形に具体化）、出口＝公開の最終確認。中間の工程はすべて自動で回す。**ただし編集の判断が要る箇所は人間が担う（同日午後の本人の整理：「判断が入るときがあるが、簡単ならいい」）。条件は判断が簡単であること：判断は提示された候補・案への応答（選ぶ／可否を返す／軽く直す）に限定し、素材を探す・全編を見る・自分で切る等の重い作業は機械側が持つ。**

## 「仕事が消えた」の定義（成功条件）

- 開催後、人の定期作業なしに公開まで完了する
- 人の関与は、判断が要る箇所での簡単な応答と、例外時（失敗通知への対応、判定が怪しい回の確認）のみ
- 特定の個人のPC・作業に依存しない

## 対象範囲

- 主対象：Paper & Hacks（月4本）
- 拡大対象：他の基本イベント（形式は共通と確認済み）
- 対象工程：録画取得 → 編集 → アップロード → 通知

## 機能要件

### Must
1. **入力の自動取得**：Zoom録画と文字起こし（VTT）を、人がダウンロード・受け渡ししなくてよい
2. **編集の自動実行**（現行仕様を踏襲）：
   - 登壇者の開始点でカット（VTTの話者ラベル＋紹介パターンで判定）
   - OP/ED素材（画像/動画）の接続＋ディゾルブ
   - 3秒以上の無音カット＋つなぎ目ディゾルブ
3. **公開までの自動化**：YouTubeへ非公開でアップロードし、タイトル等のメタデータを付ける。公開への切り替えだけ人が最終確認として行う（決定事項1）
4. **通知**：完了・失敗をコミュニティ内に通知する。失敗は人が確実に気づける形で
5. **例外の振り分け**：登壇者判定の確信度が低い回は自動で進めず、人の確認に回す

### Should
6. 台帳の自動生成（回・日時・登壇者・公開URLの一覧）
7. 他イベントへの横展開が、設定追加のみでできる

### Won't（今回やらない）
- 字幕の本格編集・校正
- 切り抜き／ショート動画の生成
- サムネイルの新規デザイン

## 非機能要件

### Must
1. **個人PCに依存しない**：クラウドまたは共用環境で稼働する
2. **保守が個人に依存しない**：SaaS/APIの活用、または手順書レベルで引き継げる構成
3. **品質は現行の公開動画と同等**：現行仕様を開始点・無音・ディゾルブの基準とする（決定事項3）
4. **コスト上限は月2,000円以内**（決定事項2）
5. **処理時間**：97分の動画の編集・エクスポートを **15分以内（目標9分）** で終える。現行は本人のPCで約60分（2026-11-21 本人報告）。実行環境のスペックとパイプライン側の高速化の両面で満たすこと

## 決定事項（2026-11-21 本人決定）

| # | 論点 | 決定 | 影響 |
|---|---|---|---|
| 1 | 公開の線引き | **B. アップロードまで自動、公開だけ人が最終確認** | 自動アップロードは非公開（または限定公開）で行い、人が確認して公開に切り替える。「確認」は残るが、動画チーム4人の誰でもできる数分の作業として設計し、特定個人に紐づけない |
| 2 | コスト上限 | **月2,000円以内** | 方式選定の強い制約。レンダリングAPIは長尺×月4本（約360分）で従量が上限を超えるため脱落見込み。Vrew Pro（1,980円）は金額内だが全自動ではないため別要件で脱落見込み |
| 3 | 品質の許容範囲 | **現行の公開動画と同等** | 現行仕様（開始点判定ロジック、無音3秒基準、ディゾルブ）を品質基準として固定する |
